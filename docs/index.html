Driftwood

A floating terminal panel for macOS. Press ⌃⌥T over whatever you are working in, type a command, press it again. A real login shell on a PTY, with your prompt and your $PATH, in a window that never takes focus from the app behind it.

What it does

A terminal that gets out of the way

It appears over what you are doing, and the app behind stays active

Press ⌃⌥T and the panel is there with the keyboard already in it. Press it again and the panel is gone. The editor you were in never deactivates: its title bar stays lit and its cursor stays where you left it, because Driftwood's window is a nonactivating panel that takes keystrokes without making Driftwood the frontmost application.

That is the whole design, and it is the one thing a screenshot cannot show. Watch the mock editor's title bar in the demo above while the panel comes and goes — nothing about it dims.

The panel is translucent, and blurs whatever it is over. Move it up across the code to see that: drag the empty part of the tab strip, or hold ⌘ and drag anywhere in the panel. Those are the two ways the app moves its window, and dragging inside the terminal without ⌘ selects text in both. Reset Position in the right-click menu puts it back.

Tabs, and the strip that hides itself

Each tab is its own login shell. The strip across the top appears when there are two or more and disappears when there is one, so a single-tab panel is nothing but terminal. Closing the last tab hides the panel rather than quitting Driftwood, and the next ⌃⌥T brings it back with a fresh shell.

Four themes, and your own

Driftwood Night, Ember, Paper and Mono ship with the app, and each one sets all sixteen ANSI colors plus the background, foreground, cursor, selection and tab text. Add your own in config.json and it joins the Theme menu next to the built-ins. The swatches on this page are generated from the app's own palettes, so they cannot drift from what you get.

Permissions

It asks for nothing

Driftwood runs a login shell with your full environment and can fire commands from a global hotkey. Deciding whether to trust that deserves specific claims rather than the word "private", so here they are, each one checkable in the source.

  • No Accessibility permission, and nothing that would need one. The global hotkeys are registered with Carbon's RegisterEventHotKey, which requires no permission at all. The usual alternative — an NSEvent global monitor — would have required the Accessibility grant, and Driftwood does not use one.
  • No other system permission. No Screen Recording, no Automation, no Full Disk Access. macOS never shows a consent dialog for it.
  • No network calls. There is no URLSession anywhere in the source, and no other networking API either. "Check for Updates" opens the GitHub releases page in your browser; the comparison is yours to make.
  • No telemetry, no analytics, no crash reporting. Nothing is counted and nothing is sent.
  • Three files, all of them yours to read. config.json and state.json in ~/Library/Application Support/Driftwood/, plus a log in ~/Library/Logs/Driftwood/ that is written only when you set "debug": true. Nothing else is written anywhere.
  • No Dock icon and no menu bar item. Nothing polls, nothing watches the Dock, and there is no background timer.

Driftwood is MIT licensed and the source is on GitHub. Every claim above is a grep away.

Settings

Two files you can read

There is no preferences window. Settings are two JSON files in ~/Library/Application Support/Driftwood/, and they are split by who writes them. config.json is yours: Driftwood writes it exactly once, to create it on first launch, and never again. state.json is the app's, and holds the panel's frame and whatever you picked from the right-click menu.

The split is the reason dragging the window can never clobber a hotkey you edited by hand.

{
  "shell": "/bin/zsh",
  "shellArguments": ["-l"],
  "fontNames": ["MesloLGS NF", "Menlo"],
  "hotkeys": {
    "toggle": "control+option+t",
    "focus": "control+option+f",
    "newTab": "control+option+n",
    "commands": "control+option+k",
    "quit": ""
  },
  "terminalPalette": { "ansi1": "#c64a5a" },
  "quickCommands": [
    {
      "id": "logs",
      "title": "Tail logs",
      "command": "tail -f /tmp/app.log",
      "hotkey": "control+option+1"
    }
  ],
  "debug": false
}

Every key is optional and every one has a default, so a key you delete falls back and a key Driftwood does not recognize is ignored. A file that will not parse at all is moved aside to config.json.bak rather than overwritten, so nothing you wrote is lost. Changes take effect on the next launch.

Every key, its type, its default and what it does: the configuration reference in the guide. The hotkey grammar is next to it, and custom themes are in the section above that.

Get started

Install

macOS 14 or later, Apple silicon and Intel.

Homebrew

brew trust --cask gapmiss/tap/driftwood   # required for third-party taps
brew install --cask gapmiss/tap/driftwood

The DMG

Download Driftwood.dmg, open it, drag Driftwood to Applications, then read the next paragraph before you double-click it.

The first launch is blocked, and that is expected

Driftwood is signed ad-hoc rather than notarized, so macOS refuses to open it the first time with a message that sounds worse than it is. Nothing is damaged — the app has a valid signature, it has just not been through Apple's notary service. Unblock it once:

  • macOS 15 and later: let it be blocked, then open System Settings → Privacy & Security, scroll to Security, and click Open Anyway.
  • macOS 14: right-click the app → Open → Open.
  • Either, from a terminal: xattr -dr com.apple.quarantine /Applications/Driftwood.app

From source

Needs a Swift toolchain — Xcode or the Command Line Tools. There is no Xcode project.

git clone https://github.com/gapmiss/driftwood
cd driftwood
make run

A build from source is not quarantined, so none of the Gatekeeper steps above apply to it. The full version of all of this, including where the app is once it is running, is in the guide.
